# 修复设计与引用（v1.0.0）

## 输入侧（问题②）

### 1. 统一中间表示：需求意图树（intent_tree.py）

页面 → 组件 → 修改意图三级；**每个节点带 `source`（哪条消息/哪张图）与 `confidence`**。树是下游（问题③的配置生成）的输入质量上限——输入侧的确定性从这里开始。

### 2. 假设清单机制（assumptions.py）——反幻觉核心

模型只允许记录客户**明说**的需求。三类推断项全部进独立的 `assumptions` 列表：
- 幻觉补全（VLM 输出 `present=False`，无论置信度多高——"自信的私货"最危险）；
- 低置信判定（< 0.85：卡片流还是列表拿不准）；
- 指代未闭合。

人工逐条 accept（转正进树，source=human_confirmed）/ reject（丢弃）。`dark_hallucination_count == 0` 是持续断言的硬指标。**把"模型的猜测"从暗处拿到明处定价**——思想源头：DeepEval 的 hallucination metric（无证据支撑的输出项）。

### 3. 共指消解（coref.py）

对话实体表（实体 → 提及轮次时间线）；"那个"取最近提及者；**同轮多实体或无先行 → 闭合失败 → assumptions**。LLM 只是把 NLP 共指的失败变得更有自信，所以闭合不了就显式问人，不瞎猜。

### 4. 归一前置（normalize.py）

粤语词表映射（摆呢度→放这里）+ 口水词剔除。归一是共指的前置：『摆呢度』不归一，指代链就断。

### 5. 分层置信路由 + 参考图对齐

清晰截图（≥0.85）直接进树；手绘稿（scenario=handdrawn）强制 `requires_human_review`。"像抖音那样" → `align.py`：最近模板 + 3 条差异清单，`copy_all=False` 写死在返回契约里——全量仿制（侵权+范围失控）在接口层就不存在。

## 输出侧（问题④）——半自动闭环的正确形态

**结论先行：主观验收无法形式化，设计目标是压缩确认的往返次数与单次成本，不是消灭人工确认。** AI 是提案器，不是拍板者。

### 6. 提案式修改（proposals.py）

模糊尺寸指令 → 3 候选（+15% 稳妥 / +30% 明显 / 布局重排）；模糊色彩指令 → 6 色候选色卡（低饱和深海军蓝→浅雾蓝，"高级感"的方向性编码）。**开放式审美问题降维成选择题**。

### 7. 预览截图基础设施（render.py + images.py）

配置 → 确定性渲染 → PPM 截图（Playwright headless 截图形态的最小零依赖实现；生产化时替换渲染后端，接口不变）。同一配置永远同一像素——这是 diff 可判性的前提。每候选附预览，客户看着选。

### 8. 属性断言兜底（assertions.py）——唯一 100% 自动化的环节

patch 声明的每条 from→to 逐条机检配置实际值。防止"Agent 说改了但没改"的低级事故（jest-image-snapshot 式的断言主义：截图/属性都是一等测试对象）。

### 9. 像素 diff（pixel_diff.py）

pixelmatch 思想：逐像素色差 + 阈值 → 变化率 + 区域 bbox。它回答"变在哪、变了多大"，不回答"改对了没有"——后者是客户的眼睛 + 提案点选。与属性断言互补：断言证明"改了"，diff 展示"改哪了"。

### 10. 往返计数与升级（rounds.py）

同一处修改第 3 轮未确认 → 升级转人工 + 事件留痕；确认后计数归零。防止审美死胡同烧 token——**这是把问题④天花板（半自动）转化为运营纪律的机制**。

## 显式不做（边界）

- 不接真实 VLM/ASR（Mock 协议与 OmniParser 对齐，替换点隔离在 mock_vlm/mock_asr）；
- 不做客户历史偏好学习（源文档 3.2 表格中的第 4 类方案——数据积累后再议）；
- 不做双端渲染差异处理（渲染器单端；双端预览属生产化工程量）。
