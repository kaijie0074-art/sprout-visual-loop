## 问题链

### Q1（起点①）手绘稿识别率"骤降"是否存在？

**假设**：同一布局，sketch 风格（灰色抖动描边）比 clean 风格（彩色填充）的组件识别率显著下降——这是仓库场景库 `handdrawn`（conf 0.31→0.4、强制人工）的预设。

**实验**：2 布局 × 2 风格 × 2 次重复（8 调用），同几何、同 GT。

**数据**：

| 图 | 风格 | recall | 自报 conf | review |
|---|---|---|---|---|
| video_feed | clean | 0.25 | **1.0** | false |
| video_feed | sketch | 0.25 | **1.0** | false |
| content_home | clean | 0.60 | **1.0** | false |
| content_home | sketch | 0.60 | **1.0** | false |

**结论（假设被拒绝 + 两个意外发现）**：
1. 骤降**不存在**——sketch 与 clean 逐对相等。但这不是"手绘没问题"，而是**地板效应**（见 Q5）：基线本身已低到 fidelity 无法再造成下降。
2. **自报置信度坍缩**：glm-4v-flash 对所有组件输出常数 `confidence=1.0`，产品里 `CONF_THRESHOLD=0.85` 的分层置信路由在真实模型上是**死代码**——低置信组件永远不会进 assumptions。
3. **review 标志失效**：sketch 页 `requires_human_review` 恒 false，产品假设"模型会自报手绘稿"不成立（glm-5.3-flash 会，见 Q7）。

### Q2（起点②）卡片流 vs 列表的歧义：0.55 置信从哪来？

**假设**：存在一条"卡片流→竖直列表"的连续谱，模型在中间地带给出中等置信（场景库 0.55 的预设）。

**实验**：morph 谱 t∈{0, .25, .5, .75, 1}（卡片宽 300→448、图区从"顶部大图"滑向"左侧缩略"、文字跟随），×2 重复。

**数据**（glm-4v-flash）：

| t | GT | 模型输出 | 自报 conf |
|---|---|---|---|
| 0.00 | feed_cards | `feed_cards` ✓ | 1.0 |
| 0.25 | feed_cards | `rectangle`, `horizontal_line` | 1.0 |
| 0.50 | list | `rectangle`, `line` | 1.0 |
| 0.75 | list | `rectangle`, `horizontal_lines` | 1.0 |
| 1.00 | list | `feed_cards` ✗ | 1.0 |

**结论**：小模型不会"给出中等置信"，它在歧义区**逃逸到基本形状词汇**（rectangle/line），且纯列表页被误判为 feed_cards。置信度不是连续信号，而是 {1.0, 0.5, 偶发} 的量化值——**校准不存在的证据**，`0.55` 这类场景值是脚本幻想。

### Q3（起点③）组件数量上限：完整性衰减曲线

**假设**：组件实例数 5/10/20/40，识别完整性随密度单调衰减，存在可测上限。

**实验**：恰好 n 个实例的页面（5/10/20/40，GT 实例清单精确）×重复。

**数据**（类型级 recall / 检出组件数）：

| n 实例 | recall | det | 事件 |
|---|---|---|---|
| 5 | 0.40 | 2-3 | `page_kind=login_screen`（页面无登录） |
| 10 | 0.14-0.29 | 2-3 | `logo/login_form` 幻觉；一次 9 组件幻觉爆发（见 Q6） |
| 20 | 0-0.14 | 1-8 | 唯一一次阶梯置信（0.2-0.8）；一次畸形 JSON |
| 40 | 0.17 | 2 | 只剩 `banner+feed_cards` |

**结论**：完整性随密度陡降（0.4→0.17），且**密度升高诱发幻觉**：无登录页被稳定标为 login；dense 页偶发 community/mall/search 全家桶。工程上限 ≈ **n≤10 时勉强可用（仍需人工兜底）**。

### Q4（起点④）嵌套/悬浮布局的置信衰减

**假设**：嵌套深度与悬浮层使置信度衰减（可测曲线）。

**实验**：depth∈{1,2,3} × overlay∈{none, fab, modal}，9 页。

**数据**：

| 页 | 结果 |
|---|---|
| d1_none | 2 组件，0.25 |
| d2/d3 多数 | **畸形 JSON**（5/9 页 `{ {` 双开括号，原实现直接崩） |
| d2/d3_fab | 0 recall（fab 未检出，banner 为幻觉） |
| 全部 | `container`/`modal` **零检出** |

**结论**：衰减曲线测不出来——在嵌套≥2 时模型输出先**格式崩坏**（深缩进诱发双花括号，6/40 全局复现率），语义上容器/弹窗/悬浮按钮**全部不可见**。结构性词汇（container/modal）超出该规模模型的页面词汇表。

### Q5（Q1 追问）地板效应验证：低保真两轴扫描

**假设（替代）**：Q1 无骤降是因为 fidelity 变化没到阈值；沿"手抖幅度 σ"与"降采样"两轴扫描应出现拐点。

**实验**：sketch σ∈{1.6, 4, 8}px（8px 时边框已明显歪扭）+ clean 降采样 480→240/120 宽，×2。

**数据**：recall 全部 0.25，检出恒为 `{tab_bar, feed_cards}` 或 `{banner, feed_cards}`，自报 conf 恒 1.0。

**结论**：**两个轴都平**。识别是"格式塔级"的（整页像 feed+tabbar 就报这两个），单组件 fidelity 对它无影响。工程上意味着：**不能用降质图像来"诱发"模型自报不确定**——它对自己的格式塔判断永远自信。假设链在此收敛到模型限制（连续第 1 问）。

### Q6 确定性与校准：单次调用可信吗？

**假设**：同一输入重复调用，输出稳定（API 温度未显式设置）。

**实验**：video_feed_clean ×5、count_10 ×3。

**数据**：
- video_feed_clean：**5 次调用 3 种组件集合签名**（banner↔logo 摆动），conf 恒 1.0。
- count_10：3 次 3 种；其中一次幻觉爆发——`community/mall/search/video_feed/login_form` 全部 present@0.5、`login_form@1.0`（页面上都不存在）。

**结论**：**非确定性 + 校准坍缩**叠加：幻觉组件以 present=true、conf=1.0 直通需求树，反幻觉门（0.85 阈值）形同虚设（连续第 2 问收敛）。

### Q6' 工程修复（不换模型能救多少？）

两项修复（已合入产品代码，离线 29 测试全绿 + live 验证）：

1. **`parse_model_json`**（`visual_loop/vlm.py`）：容忍实测畸形——code fence、`{ {` 双开括号（含配对尾括号）、截断。**5/5 真实故障输出回放修复成功**（`evidence/deep-dive-20261014/json_failure_fixtures.json`）。
2. **`describe_stable(image, k)` + `build_intent_tree(stable_k=3)`**：自报置信→**跨采样一致率**（经验置信度）。缺席=反对票；`page_kind_stable` 显式标注。

**live 验证**（`stable_results.jsonl`）：
- `count_10.png`（歧义密集页）：最高一致率 `login_form 0.667 < 0.85` → **全部组件进 assumptions，零直通**——正是反幻觉门需要的保守行为；
- `sketch_w016.png`（清晰格式塔页）：`feed_cards/tab_bar` 3/3=1.0 → 直通需求树。
- **残余盲区**：`page_kind=login_screen`（幻觉）跨采样**稳定**——一致的幻觉不可被一致性捕获。这是该方法原理性边界（连续第 3 问收敛）。

### Q7 更强模型能解除瓶颈吗？

**实验**：glm-5.3-flash 跑三个最差页（sketch / count_20 / nested_d3_none）。

| 页 | 4v-flash | 5.3-flash | 5.3 表现 |
|---|---|---|---|
| video_feed_sketch | 0.25 / conf 1.0 / review false | **0.50 / conf 0.4-0.85 / review true** | 阶梯置信恢复，手绘自报 review ✓ |
| count_20 | 0-0.14（含 JSON 崩） | **0.571**（fab/tab_bar/图标全对，无 login 幻觉） | 密度上限大幅抬升 |
| nested_d3_none | 0（JSON 崩） | 0.25 | **container 仍不可见**；review true |

代价：延迟 1.5-5s → **12-21s（×4-10）**。

**结论**：校准、review 自报、密度上限都是**规模问题**（5.3 恢复）；但嵌套容器词汇、稳定幻觉不可捕获是共同残留；延迟使交互式反馈循环（用户等确认）难以承受。

## 停止条件判定

连续三问（Q5 → Q6(+Q6' 残余) → Q7）收敛到同一类限制：**小规模 VLM 的页面级结构化感知上限**——
(a) 置自报校准坍缩（常数 1.0）；(b) 采样非确定性（5 次 3 种结果）与稳定幻觉；(c) 格式稳定性随页面复杂度崩坏（6/40 畸形 JSON）；(d) 结构词汇（container/modal）缺失。
工程手段（JSON 修复、k 采样一致率路由）只能把不可靠输出**保守导流**到人工确认，不能提升感知本身；提升只有换更大模型（recall +0.2~0.43），代价 ×4-10 延迟。**触发停止条件①**。

## 瓶颈一句话

> glm-4v-flash 的"自报置信度"坍缩为常数 1.0 且同图多次采样非确定（5 次 3 种组件集合），叠加深嵌套页 6/40 概率输出畸形 JSON——单次 VLM 调用的结构化页面描述不可信；工程只能用跨采样一致率把它降级为"可信的保守路由"（自动转人工），感知地板（类型 recall 0.17-0.4）只有模型规模能抬升。
