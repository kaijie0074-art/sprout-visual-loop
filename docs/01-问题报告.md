# 问题报告：视觉反馈闭环不可用（输入侧脏输入直通 / 输出侧零验证）

- **编号**：对应仓库 Issue #1
- **严重度**：P1（输入侧：需求文档夹带私货 → 返工撕扯；输出侧："说改了没改"事故 + 审美死胡同烧 token）
- **影响面**：所有客户需求录入与视觉迭代轮次
- **报告日期**：2026-10-13
- **状态**：已修复（v1.0.0，PR #2）

## 1. 输入侧（问题②）：多模态脏输入 → 结构化需求

客户的需求表达 = 微信截图 + 60 秒无标点方言语音 + 手绘原型稿 + "做个像抖音那样的"。现状是**直通管线**：VLM/ASR 输出直接当需求文档用。

| # | 难点 | 现状后果 | 复现测试 |
|---|---|---|---|
| I1 | UI 参考图组件类型判定不稳（卡片流还是列表？） | 判错则下游选型全错 | `test_low_confidence_to_assumptions` |
| I2 | 手绘稿识别率骤降 | 猜测当结论用 | `test_handdrawn_routes_to_human_review` |
| I3 | 指代与省略（"那个放左边"） | 修改意图绑不到目标实体 | `test_reference_resolved_to_last_entity` / `test_ambiguous_*` / `test_unresolved_*` |
| I4 | 方言与转写噪音（"摆呢度""睇下"） | 关键词全部漏提 | `test_cantonese_*` |
| I5 | **幻觉补全（最危险）**：客户没提登录页，模型按"常见 APP 该有的样子"悄悄加 | 需求夹带私货，验收时才发现"我没要过这个" | `test_hallucinated_component_captured` / `test_dark_hallucination_zero` |
| I6 | 参考图被解析成全量仿制 | 侵权 + 范围失控 | `test_align_to_template_with_diffs` |

## 2. 输出侧（问题④）：像素级反馈的自动验收

"logo 再大一点""高级点的蓝"——**主观验收标准无法形式化**，自动化天花板是半自动。但现状连半自动的下限都没守住：

| # | 缺失 | 后果 | 复现测试 |
|---|---|---|---|
| O1 | 无属性断言 | "Agent 说改了但没改"直通客户 | `test_noop_change_caught` |
| O2 | 模糊指令单点拍板 | 一个数/一个色值直接上，往返撕扯 | `test_resize/color_proposes_*` |
| O3 | 无预览截图基础设施 | 提案式交互无从谈起 | （候选附 preview） |
| O4 | 无像素 diff | 变化位置/面积不可见 | `test_logo_resize_detected_*` |
| O5 | 无往返计数 | 同一处修改无限轮打转烧 token | `test_third_unconfirmed_round_escalates` |

## 3. 验收判据（源文档 3.4）

| 判据 | 实测（v1.0.0） |
|---|---|
| 幻觉率 < 5% 且全部被 assumptions 捕获，暗幻觉 = 0 | ✅ 幻觉项 100% 进 assumptions；`dark_hallucination_count == 0` |
| 指代：混合输入指代准确率（闭合的显式处理） | ✅ 唯一先行正确绑定；歧义/悬空显式转人工，不瞎猜 |
| 属性断言自动化覆盖率 100% | ✅ 声明的改动逐条机检，noop 必被抓 |
| 平均确认往返 ≤ 2 轮（提案式） | ✅ 架构就绪：3 尺寸候选/6 色卡+预览；超 2 轮升级转人工 |
